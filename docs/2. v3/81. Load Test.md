# TAMMY v3 백엔드 부하 테스트 및 성능 검증 사양서 (Backend Load Testing & Performance Specification)

본 문서는 TAMMY v3 백엔드 시스템의 트래픽 처리 성능, 초당 처리 건수(TPS), 응답 시간(Latency SLA) 목표를 수립하고, k6 기반의 부하 테스트 시나리오 및 병목 튜닝 가이드라인을 정의한 전용 사양서입니다.

---

## 1. 개요 및 목표 (Overview & SLA Goals)

- **목적**: 동시 접속자 폭증 및 AI/식단 스캔 요청 집중 시 백엔드 시스템의 안정성 검증 및 병목 지점 사전 해소.
- **성능 측정 가이드라인**:
  - **TPS (Transactions Per Second)**: 초당 처리 완료 가능한 API 요청 건수
  - **Latency p95 (95th Percentile)**: 전체 요청 중 상위 95% 유저가 체감하는 응답 속도 (ms)
  - **Error Rate**: 전체 요청 대비 5xx/4xx 오류 발생 비율 (목표: 0.1% 미만)

## 3. 부하 테스트 4대 전략 (Testing Strategies)

### 3.1 Load Test (일상 평균 부하 테스트)
- **목적**: 평시 목표 트래픽(예: 200~300 TPS) 환경에서 시스템이 목표 SLA를 충족하는지 검증.
- **조건**: 가상 유저(VU) 100명, 10분간 지속 유지.

### 3.2 Stress Test (한계 및 임계점 테스트)
- **목적**: 서버가 견딜 수 있는 최대 한계 트래픽(Break-Point) 탐색.
- **조건**: VU를 50 ➡️ 200 ➡️ 500 ➡️ 1,000 명으로 단계적 증대(Ramp-Up).

### 3.3 Spike Test (순간 트래픽 폭주 테스트)
- **목적**: 안부 톡 푸시 알림 송신 시 순식간에 몰리는 부하 대응력 검증.
- **조건**: 10초 이내에 VU 0명 ➡️ 500명으로 급증 후 시스템 자동 복구 여부 확인.

### 3.4 Soak / Endurance Test (내구성 테스트)
- **목적**: 장시간 부하 환경에서 Node.js 이벤트 루프 차단 또는 메모리 누수(Memory Leak) 유무 검증.
- **조건**: 목표 트래픽 환경에서 12시간~24시간 장시간 지속 부하 투입.

## 4. k6 시나리오 테스트 스크립트 규격 (k6 Scenario Specifications)

k6 실행을 위한 표준 자바스크립트 부하 테스트 시나리오 구성 규격입니다.

***
[k6 테스트 실행 명령어 예시]
k6 run --vus 100 --duration 5m scripts/load_test_main.js
***

***
[k6 시나리오 스크립트 작성 가이드라인]

- thresholds 설정:
  http_req_duration: ['p(95)<200'] // 95% 요청이 200ms 이내
  http_req_failed: ['rate<0.001']   // 에러율 0.1% 미만

- 사용자 행동 시나리오 (User Journey Flow):
  1. GET /api/users/me (프로필 조회)
  2. GET /api/care/daily-summary (오늘의 웰니스 수치)
  3. POST /api/workout/check (1-Tap 운동 완료 체크)
  4. GET /api/food/master/search?query=연어 (표준 음식 검색)
***

## 5. 성능 병목 진단 및 튜닝 파이프라인 (Bottleneck Tuning)

### 5.1 DB 슬로우 쿼리 & 복합 인덱스 최적화
- `EXPLAIN` 구문을 통한 쿼리 실행 계획 분석.
- `exercise_logs` 커서 동기화 인덱스 (`user_id, id ASC`) 및 시계열 로그 인덱스 검증.

### 5.2 Redis In-Memory 캐싱 전략
- 초고빈도 조회인 `foods` 마스터 데이터 및 `planets` 정보는 Redis에 캐싱하여 MySQL DB 부하 90% 이상 차단.

### 5.3 프로세스 확장 & Connection Pool
- Node.js 멀티 코어 활용을 위한 `PM2 Cluster Mode` 실행.
- MySQL/Prisma 커넥션 풀(`connection_limit=50`) 및 비동기 작업 큐 적용.
