# ⚙️ TAMMY v3 API 수신 후 비즈니스 로직 실행 명세서 (Post-API Business Logic Workflows)

본 문서는 **TAMMY v3 백엔드 API 시스템(전체 21개 API)**이 클라이언트(FE)로부터 각 API 요청을 수신한 직후, 백엔드(BE) 내부에서 수행하는 **DB 트랜잭션, 게이미피케이션 보상 계산, 외부 AI 통신, 비동기 파이프라인, 푸시 알림 및 이벤트 처리 흐름**을 빠짐없이 세부 정의한 통합 명세서입니다.

---

## 🔑 1. 회원 인증 & 계정 관리 API 비즈니스 로직 (`/api/auth/*`)

### 1.1 `POST /api/auth/signup` (회원가입 수신 후)
- **Step 1 (이메일 중복 체크)**: `users.findUnique`를 수행하여 동일 이메일 계정이 존재하는지 확인. 존재 시 `409 CONFLICT` 반환.
- **Step 2 (비밀번호 보안 암호화)**: `argon2.hash(password)`로 단방향 보안 해시 생성.
- **Step 3 (DB 원자적 트랜잭션 적재)**: `prisma.users.create`를 통해 아래 3개 레코드를 단일 트랜잭션으로 자동 연동 생성:
  - `users`: 신규 계정 생성 (`status: ACTIVE`, `auth_provider: LOCAL`)
  - `tammy_statuses`: 초기 타미 펫 레벨 1, EXP 0, 4대 지수(공감/건강/활동/행복) 50으로 자동 생성
  - `space_travel_states`: 1번 행성("아쿠아 웰니스 행성"), 보유 연료 0 Fuel, 우주선 초기 좌표(0,0) 세팅
- **Step 4 (토큰 발급 & 세션 등록)**: 
  - Access Token(1시간) 및 Refresh Token(14일) 발급
  - `users.refresh_token` 및 `last_login_at` 시각 DB 저장
- **Step 5 (클라이언트 응답)**: 유저 기본 프로필 및 토큰 쌍을 201 Created로 반환.

### 1.2 `POST /api/auth/login` (로그인 수신 후)
- **Step 1 (계정 검증)**: DB 이메일 조회 후 `argon2.verify`로 비밀번호 비교 (실패 시 `401 UNAUTHORIZED` 반환).
- **Step 2 (세션 갱신 & 토큰 발급)**:
  - 로그인 성공 시 DB `last_login_at` 시각을 현재 시각으로 갱신
  - 신규 Refresh Token DB 업데이트 및 Access Token과 함께 200 OK 반환.

### 1.3 `POST /api/auth/logout` (로그아웃 수신 후)
- **Step 1 (세션 무효화)**: 제출된 토큰의 유저 DB `users.refresh_token` 필드를 `null`로 변경하여 세션 즉시 무효화.
- **Step 2 (응답)**: 로그아웃 완료 메세지 200 OK 반환.

### 1.4 `POST /api/auth/refresh` (토큰 자동 갱신 수신 후)
- **Step 1 (Refresh Token 검증)**: 제출된 Refresh Token의 서명/만료 및 DB 저장 토큰과의 일치 여부 대조 (RTR 보안 정책).
- **Step 2 (재발급)**: 신규 Access/Refresh Token 쌍 발급 후 DB 저장 업데이트.

### 1.5 `GET /api/auth/me` (내 계정 인증 정보 조회 수신 후)
- **Step 1 (유저 검증 및 조회)**: JWT 토큰에서 `userId` 파싱 후 `users.findUnique`로 유저 이메일, 닉네임, 가입일 등 기본 정보 조회.
- **Step 2 (응답)**: 계정 프로필 데이터 200 OK 반환.

### 1.6 `DELETE /api/auth/withdraw` (회원 탈퇴 수신 후)
- **Step 1 (데이터 파기)**: `prisma.users.delete`를 실행하여 펫, 우주선, 대화, 식단 등 관련 Cascade 데이터 완전 삭제 (또는 `WITHDRAWN` 상태 변경).
- **Step 2 (응답)**: 회원 탈퇴 완료 메시지 반환.

## 👤 2. 내 프로필 & 타미 성장 히스토리 API 비즈니스 로직 (`/api/users/*`)

### 2.1 `GET /api/users/me` (내 프로필 및 타미 상태 통합 조회 수신 후)
- **Step 1 (연관 DB 3종 조인 조회)**: `prisma.users.findUnique`를 실행하여 `users` 계정 정보, `tammy_statuses` 펫 레벨/EXP/지수, `space_travel_states` 우주선 연료 정보를 한 번에 연관 조회.
- **Step 2 (응답)**: 유저 신체 목표 + 타미 상태를 통합하여 200 OK 반환.

### 2.2 `GET /api/users/tammy/history` (타미 성장 일지 히스토리 조회 수신 후)
- **Step 1 (로그 DB 조회)**: `tammy_status_logs` 테이블에서 해당 유저의 펫 경험치/지수 변동 이력을 최신순(`desc`)으로 최대 20건 조회.
- **Step 2 (응답)**: 경험치 획득 사유, 변동 수치, 당시 레벨 스냅샷 배열 반환.

## 💬 3. AI 심리 공감 대화 & 장기 기억 캡슐 API 비즈니스 로직 (`/api/ai/*`, `/api/chat/*`)

### 3.1 `POST /api/ai/chat` (AI 타미 심리 대화 수신 후)
- **Step 1 (유저 메시지 DB 적재)**: `chat_messages` 테이블에 사용자 입력 메시지(`sender: USER`) 저장.
- **Step 2 (장기 기억 추출 & AI 2차 요청)**:
  - `long_term_memories` DB에서 해당 유저의 최근 주요 기억 캡슐 상위 5건 추출
  - AI 대화 서버 (`POST http://ai-server:8000/v1/chat/process`)로 2차 HTTP 요청 전송
- **Step 3 (AI 분석 응답 처리)**:
  - 타미 공감 응답 텍스트를 `chat_messages` (`sender: TAMMY`)로 DB 적재
  - AI가 새로 추출한 기억 캡슐(`extractedMemory`)이 존재하면 `long_term_memories` DB에 `upsert` 저장
- **Step 4 (게이미피케이션 보상 지급)**:
  - `space_travel_states` 우주선 연료 **+10 Fuel** 충전 및 탐사 진행률 계산
  - `tammy_statuses` 공감지수 및 경험치(EXP) 상승
- **Step 5 (클라이언트 응답)**: 타미 공감 텍스트 + 모션 표정 + 획득 연료(+10)를 클라이언트에 200 OK 반환.

### 3.2 `GET /api/chat/memories` (장기 기억 캡슐 목록 조회 수신 후)
- **Step 1 (기억 DB 조회)**: `long_term_memories` 테이블에서 유저의 카테고리별 축적된 기억 캡슐 목록을 최신순 조회.
- **Step 2 (응답)**: 기억 ID, 카테고리, 내용, 생성일자 배열 반환.

### 3.3 `DELETE /api/chat/memories/:id` (장기 기억 캡슐 삭제 수신 후)
- **Step 1 (기억 삭제)**: `long_term_memories.delete`를 호출하여 특정 기억 캡슐 레코드 영구 삭제.
- **Step 2 (응답)**: 200 OK 성공 응답 반환.

## 🥗 4. 음식 비전 분석 & 식단 관리 API 비즈니스 로직 (`/api/food/*`)

### 4.1 `POST /api/food/analyze` (AI 비전 분석 스캔 수신 후)
- **Step 1 (AI 비전 서버 호출)**: 업로드된 사진 URL을 AI 비전 분석 서버 (`POST http://ai-server:8000/v1/vision/analyze-food`)로 전달.
- **Step 2 (영양소 수치 반환)**: AI가 식별한 음식명, 5대 영양소(탄/단/지/비/미 g & %) 및 예상 칼로리를 파싱하여 FE로 임시 응답 (DB 저장 안 함).

### 4.2 `POST /api/food/log` (식단 확정 등록 수신 후)
- **Step 1 (식단 DB 3종 적재)**:
  - `meals`: 식사 타입(LUNCH 등), 총 칼로리, 영양 성분 합계 및 멘트 저장
  - `meal_images`: 1:N 이미지 URL 및 커버 여부(`is_cover: true`) 저장
  - `meal_items`: 세부 포함 음식 항목 저장
- **Step 2 (게이미피케이션 보상 지급)**:
  - `space_travel_states` 우주선 연료 **+50 Fuel** 충전
  - `tammy_statuses` 경험치 **+30 EXP** 및 건강지수 증가
- **Step 3 (클라이언트 응답)**: 획득한 보상 수치(`gainedFuel: 50`, `gainedExp: 30`)를 클라이언트에 200 OK 반환.

### 4.3 `GET /api/food/search` (표준 음식 영양 마스터 자동완성 검색 수신 후)
- **Step 1 (DB 키워드 검색)**: `foods` 마스터 테이블에서 입력된 검색어(`keyword`)로 음식 이름 라이크(`LIKE %keyword%`) 검색.
- **Step 2 (응답)**: 표준 Serving 수치 및 5대 영양소 칼로리 배열 반환.

## 💧 5. 1-Tap 데일리 케어 & 운동 API 비즈니스 로직 (`/api/care/*`, `/api/exercise/*`)

### 5.1 `POST /api/care/water` (1-Tap 수분 250ml 섭취 수신 후)
- **Step 1 (기록 적재)**: `water_logs` 테이블에 250ml 섭취 타임스탬프 기록.
- **Step 2 (보상 지급)**: 우주선 연료 **+10 Fuel** 충전 및 오늘 누적 수분 섭취량 계산 후 반환.

### 5.2 `POST /api/exercise/log` (1-Tap 오늘 운동 완! 수신 후)
- **Step 1 (기록 적재)**: `exercise_logs` 테이블에 운동 완료 레코드(`is_completed: true`, 소모 칼로리) 생성.
- **Step 2 (보상 지급)**: 우주선 연료 **+30 Fuel** 충전 및 탐사 진행률 계산 후 반환.

## 🪐 6. 별여행 탐사 & 연료 충전 API 비즈니스 로직 (`/api/travel/*`)

### 6.1 `GET /api/travel/state` (우주선 & 탐사 상태 조회 수신 후)
- **Step 1 (우주선 및 행성 DB 조회)**: `space_travel_states`와 현재 위치한 `planets` 정보 조회.
- **Step 2 (진척도 계산)**: `(현재연료 ÷ 다음행성 필요연료) × 100` 탐사 진행률 계산 후 200 OK 반환.

### 6.2 `POST /api/travel/fuel` (미션 보상 연료 직접 충전 수신 후)
- **Step 1 (연료 가산)**: `space_travel_states.current_fuel` 수치 가산.
- **Step 2 (행성 개척 검사)**: 누적 연료가 현재 행성의 요구 연료(`required_fuel`) 이상에 도달하였는지 판별.
- **Step 3 (워프 이벤트 발생)**: 요구 연료 달성 시 다음 행성(`planets`)으로 위치를 이동시키고, `isWarped: true` 및 신규 행성 개척 이벤트 반환.

## 📊 7. AI 건강 인사이트 & 비동기 리포트 API 비즈니스 로직 (`/api/reports/*`, `/api/notifications/*`)

### 7.1 `GET /api/reports/dashboard` (상시 웰니스 대시보드 데이터 조회 수신 후)
- **Step 1 (주간/월간 데이터 집계)**: 최근 7일/30일간의 `water_logs`, `meals` 영양소 합계, `exercise_logs` 운동 달성률을 SQL 집계 연산.
- **Step 2 (응답)**: 5대 영양소 차트 밸런스 및 칼로리 추이 데이터 반환.

### 7.2 `POST /api/reports/generate` (비동기 리포트 생성 수신 후)
- **Step 1 (202 Accepted 즉시 응답)**: 수신 즉시 클라이언트에 `202 Accepted` 및 비동기 작업 ID(`jobId`) 반환하여 대기 방지.
- **Step 2 (백그라운드 Worker 실행)**: DB에서 사용자의 지난 주간/월간 수분, 운동, 식단, AI 대화 기억 캡슐 데이터를 비동기 추출.
- **Step 3 (AI 요약 서버 호출)**: 집계된 데이터를 AI 요약 서버 (`POST http://ai-server:8000/v1/reports/summarize`)로 전달.
- **Step 4 (DB 적재)**: AI 진단 요약문 및 웰니스 가이드를 `monthly_reports` DB에 저장.
- **Step 5 (Push Notification 발송)**: 백그라운드 작업 완료 시 등록된 디바이스 푸시 토큰(`POST /api/notifications/push-token`)으로 FCM/APNs 푸시 알림 발송.

### 7.3 `GET /api/reports/jobs/:jobId` (리포트 백그라운드 작업 상태 조회 수신 후)
- **Step 1 (작업 진행도 조회)**: `report_jobs` 비동기 작업 테이블에서 지정된 `jobId`의 상태(`PENDING` | `COMPLETED` | `FAILED`) 및 진척도(%) 조회 후 반환.

### 7.4 `GET /api/reports/:reportId` (생성 완료된 리포트 상세 조회 수신 후)
- **Step 1 (리포트 조회)**: `monthly_reports` 테이블에서 해당 `reportId` 레코드를 조회하여 AI 총평, 웰니스 점수, 추천 미션 반환.

### 7.5 `POST /api/notifications/push-token` (Push Notification 디바이스 토큰 등록 수신 후)
- **Step 1 (토큰 저장)**: `user_push_tokens` 테이블에 사용자 ID와 FCM/APNs 디바이스 토큰, 플랫폼(IOS/ANDROID) 정보를 `upsert` 저장.

- **Step 1 (비동기 배치 적재)**: 클라이언트에서 수집된 화면 스크롤, 버튼 클릭 등 행동 분석 데이터를 `user_action_logs` 테이블에 비동기 배치 적재.
