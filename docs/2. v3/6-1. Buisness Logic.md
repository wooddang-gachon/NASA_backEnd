# ⚙️ TAMMY v3 API 수신 후 비즈니스 로직 실행 명세서 (Post-API Business Logic Workflows)

본 문서는 **TAMMY v3 백엔드 API 시스템**이 클라이언트(FE)로부터 각 API 요청을 수신한 직후, 백엔드(BE) 내부에서 수행하는 **DB 트랜잭션, 게이미피케이션 보상 계산, 외부 AI 서버(tammy-agent) 연동, 비동기 파이프라인, 푸시 알림 및 이벤트 처리 흐름**을 세부 정의한 통합 명세서입니다.

---

## 🏗️ 1. FE - BE - AI 3자 파이프라인 및 백엔드 비즈니스 아키텍처

```
+------------------+         +--------------------+         +-----------------------+
|  FE (Client App) | <-----> | BE (Node/Express)  | <-----> | AI (tammy-agent Fast) |
+------------------+         +--------------------+         +-----------------------+
        |                             |                             |
        | 1. 식사사진 스캔            | /v1/vision/analyze-food     |
        | --------------------------> | --------------------------> |
        |                             | <-------------------------- |
        |                             | 2. 음식명 & 4대영양소 파싱  |
        | 3. 식사일기(diary) 작성     |                             |
        |    + 식단 확정              |                             |
        | --------------------------> | DB 저장 (meals, diary)      |
        |                             |                             |
        |                             | 4. 식사일기 대화 물꼬 연동  |
        |                             | /v1/chat/process            |
        |                             | --------------------------> |
        |                             | <-------------------------- |
        | <-------------------------- | 5. 타미 공감 대화 반환      |
```

## 🥗 2. 음식 비전 스캔 & 식단 확정 + 식사 일기 비즈니스 로직 (`/api/food/*`)

### 2.1 `POST /api/food/analyze` (AI 비전 스캔 수신 후)
- **Step 1 (AI 비전 서버 1차 통신)**: 이미지 URL을 AI 비전 서버 (`POST http://ai-server:8000/v1/vision/analyze-food`)로 전달.
- **Step 2 (DB 스키마 매핑 영양성분 파싱)**: AI가 식별한 음식명 및 백엔드 DB 스키마(`meals`/`foods`)에 정의된 **4대 영양성분(칼로리 `total_calories_kcal`, 탄수화물 `total_carbohydrate_g`, 단백질 `total_protein_g`, 지방 `total_fat_g`) 및 5대 영양소 지수**를 파싱하여 FE에 임시 응답 (DB 저장 안 함).

### 2.2 `POST /api/food/log` (식단 확정 등록 + 100자 식사 일기 & 대화 물꼬 수신 후)
- **Step 1 (식단 DB 적재)**: `meals` 테이블에 식사 종류, 총 칼로리, 4대 영양소 수치와 함께 유저가 작성한 100자 이내 **식사 일기(`diary`)**를 적재. `meal_images` 및 `meal_items` 테이블 연관 저장.
- **Step 2 (식사 일기 ➔ 타미 대화 물꼬 자동 연결)**:
  - 식사 일기(`diary`) 문장이 작성된 경우, 백엔드가 해당 일기 텍스트를 AI 심리 대화 엔진 (`POST http://ai-server:8000/v1/chat/process`)으로 자동 전달하여 대화의 물꼬를 틈.
  - AI가 식사 일기에 담긴 유저의 심리 상태(예: "오늘 업무 스트레스로 매운 게 당겼지만 샐러드로 참았다")를 파악하여 타미의 첫 마디 공감 응답(`tammyChatReply`)을 즉시 생성.
- **Step 3 (게이미피케이션 보상 지급)**:
  - `space_travel_states` 우주선 연료 **+50 Fuel** 충전
  - `tammy_statuses` 경험치 **+30 EXP** 및 건강지수 상승
- **Step 4 (FE 응답)**: 보상 수치(`gainedFuel: 50`, `gainedExp: 30`)와 타미의 식사 일기 공감 대화 물꼬 응답(`tammyChatReply`)을 클라이언트에 200 OK로 반환.

### 2.3 `GET /api/food/search` (표준 음식 영양 검색 수신 후)
- **Step 1 (DB 마스터 조회)**: `foods` 테이블에서 검색어(`keyword`)로 음식 영양 데이터 라이크 검색 후 반환.

## 💬 3. AI 심리 공감 대화 & 대화 압축/기억 선별 비즈니스 로직 (`POST /api/ai/chat`, `/api/chat/*`)

### 3.1 `POST /api/ai/chat` (AI 타미 심리 대화 수신 후)
- **Step 1 (유저 메시지 DB 적재)**: `chat_messages` 테이블에 사용자 입력 메시지(`sender: USER`) 저장.
- **Step 2 (대화 맥락 구조체 `memory` 구성 & AI 연동)**:
  - `long_term_memories` DB에서 대화 압축 문장(`recent_records`) 및 맥락 구조체(`memory`) 구성:
    ```json
    "memory": {
      "today": "2026-08-04",
      "weather": "SUNNY",
      "tammy": { "name": "타미", "level": 1, "days_together": 10 },
      "recent_records": ["다이어트 스트레스 해소로 매운 음식을 선호함"]
    }
    ```
  - AI 대화 서버 (`POST http://ai-server:8000/v1/chat/process`)로 2차 HTTP 요청 전송.
- **Step 3 (AI 응답 & 신규 기억 선별/저장)**:
  - 타미 공감 응답 텍스트를 `chat_messages` (`sender: TAMMY`)로 DB 적재
  - AI가 대화 내용 중 장기 유지 가치가 있는 컨텍스트를 선별하여 `newMemoryContent`를 반환한 경우, `long_term_memories` DB에 `upsert` 저장.
- **Step 4 (게이미피케이션 보상 지급)**:
  - `space_travel_states` 우주선 연료 **+10 Fuel** 충전 및 탐사 진행률 계산
  - `tammy_statuses` 공감지수 및 경험치(EXP) 상승.
- **Step 5 (FE 응답)**: 타미 공감 텍스트 + 모션 표정 + 획득 연료(+10)를 클라이언트에 반환.

### 3.2 `GET /api/chat/memories` (장기 기억 캡슐 조회 수신 후)
- `long_term_memories` DB 목록 최신순 조회 후 반환.

### 3.3 `DELETE /api/chat/memories/:id` (장기 기억 캡슐 삭제 수신 후)
- 지정된 기억 캡슐 DB 레코드 영구 삭제.

## 💧 4. 1-Tap 데일리 케어 & 신체 활동 비즈니스 로직 (`/api/care/*`, `/api/exercise/*`)

### 4.1 `POST /api/care/water` (1-Tap 수분 섭취 250ml / 기타 섭취 수신 후)
- **Step 1 (기타 섭취 DB 적재)**: `water_logs` (`other_intakes` 데이터 모델: `type: WATER`, `value: 250`, `unit: ml`)에 타임스탬프 저장.
- **Step 2 (보상 지급)**: 우주선 연료 **+10 Fuel** 충전 및 누적 수분량 반환.

### 4.2 `POST /api/exercise/log` (1-Tap 오늘 운동 완! & 신체 활동 수신 후)
- **Step 1 (활동 DB 적재)**: `exercise_logs` (`activities` 데이터 모델: `type: WORKOUT`, `duration_minutes: 30`, `note: 메모`)에 완료 레코드 생성.
- **Step 2 (보상 지급)**: 우주선 연료 **+30 Fuel** 충전 및 탐사 진행률 계산 후 반환.

## 📊 6. AI 3종 건강 리포트 비동기 생성 비즈니스 로직 (`/api/reports/*`)

### 6.1 `GET /api/reports/dashboard` (상시 웰니스 대시보드 조회 수신 후)
- 최근 7일/30일간의 섭취, 운동, 대화 지수 SQL 집계 데이터를 차트용으로 반환.

### 6.2 `POST /api/reports/generate` (AI 3종 리포트 비동기 생성 수신 후)
- **Step 1 (202 Accepted 즉시 응답)**: 수신 즉시 클라이언트에 `202 Accepted` 및 비동기 작업 ID(`jobId`) 반환.
- **Step 2 (백그라운드 Worker 집계 파이프라인)**:
  - 지정된 리포트 3종 유형(`WELLNESS` | `MINDFULNESS_DIARY` | `COMPREHENSIVE_NUTRITION_EXERCISE`) 및 기간(`period_from` ~ `period_to`)에 따라 데이터집계:
    1. **식사 일기 데이터 (`entries`)**: 식사 ID, 시각, 음식명 목록 및 유저가 작성한 **식사 일기(`diary`)** 텍스트 수집 (마음챙김 리포트 생성의 핵심 심리 데이터로 활용)
    2. **신체 활동 데이터 (`activities`)**: 운동 유형, 지속 시간, 메모
    3. **기타 섭취 데이터 (`other_intakes`)**: 수분/간식 섭취량 및 단위
- **Step 3 (AI 서버 요약 요청)**: AI 요약 서버 (`POST http://ai-server:8000/v1/reports/summarize`)로 집계된 3종 리포트 데이터 통신 전송.
- **Step 4 (DB 저장 & 푸시 알림)**: AI 분석 진단문 및 웰니스 점수를 `monthly_reports` DB에 저장하고, 등록된 디바이스 푸시 토큰(`user_push_tokens`)으로 FCM/APNs 완료 푸시 알림 발송.

### 6.3 `GET /api/reports/jobs/:jobId` (리포트 작업 상태 조회 수신 후)
- 작업 진행 상태(`PENDING` | `COMPLETED` | `FAILED`) 및 진척도 조회 반환.

### 6.4 `GET /api/reports/:reportId` (완료된 리포트 상세 조회 수신 후)
- 생성된 3종 리포트 상세 진단 결과 및 AI 맞춤 피드백 반환.

## 🔑 7. 회원 인증 & 프로필 & 행동 분석 비즈니스 로직 (`/api/auth/*`, `/api/users/*`, `/api/logs/*`)

- `POST /api/auth/signup`: 회원가입 ➔ `users`, `tammy_statuses`, `space_travel_states` 원자적 동시 생성
- `POST /api/auth/login`: `argon2` 인증 ➔ `last_login_at` 갱신 ➔ JWT 발급
- `POST /api/auth/logout`: `refresh_token` 무효화
- `POST /api/auth/refresh`: RTR 토큰 갱신
- `GET /api/auth/me`: 계정 인증 프로필 조회
- `DELETE /api/auth/withdraw`: 회원 탈퇴 및 데이터 파기
- `GET /api/users/me`: 내 프로필 및 타미 상태 통합 조회
- `GET /api/users/tammy/history`: 타미 성장 히스토리 조회
- `POST /api/logs/action`: 클라이언트 행동 분석 데이터 비동기 적재
