# TAMMY v3 API 수신 후 비즈니스 로직 실행 명세서 (Post-API Business Logic Workflows)

본 문서는 **TAMMY v3 백엔드 API 시스템**이 클라이언트(FE)로부터 각 API 요청을 수신한 직후, 백엔드(BE) 내부에서 수행하는 **DB 트랜잭션, 게이미피케이션 연료 보상 계산, 하이브리드 비전 검토, AI-server 연동, 비동기 Task Queue, 푸시 알림 및 이벤트 처리 흐름**을 세부 정의한 명세서입니다.

---

## 1. FE - BE - AI 3자 파이프라인 및 백엔드 비즈니스 아키텍처

```
+------------------+         +--------------------+         +-----------------------+
|  FE (Client App) | <-----> | BE (Node/Express)  | <-----> | AI-server (LLM Engine)|
+------------------+         +--------------------+         +-----------------------+
        |                             |                             |
        | 1. 식단 사진 스캔           | 2. BE 512px 압축            |
        | --------------------------> |    + YOLO 1차 검토          |
        |                             | 3. 미식별 시 Fallback 요청  |
        |                             | --------------------------> |
        |                             | <-------------------------- |
        | <-------------------------- | 4. 최종 영양 데이터 반환    |
        | 5. 수동 검수 & 식단 확정    |                             |
        | --------------------------> | DB 저장 (food_logs)         |
        |                             |                             |
        | 6. 사용자 메시지 전송       | 7. DB 즉시 선저장           |
        | --------------------------> | 8. 메시지 전달 & 종합 가공  |
        |                             | --------------------------> |
        |                             | <-------------------------- |
        | <-------------------------- | 9. 공감 답변 DB저장 & 반환  |
```

---

## 2. 1-Tap 퀵버튼 데일리 기록 비즈니스 로직 (`POST /api/v3/quick-log`)

- **Step 1 (DB 기록 적재)**: `quick_logs` 테이블에 `category` (WATER, EMOTION, JOURNAL, EXERCISE)별 데이터 저장
- **Step 2 (연료 보상 계산)**: 사용자 `currentFuel` 포인트를 +10 Fuel 가산하여 DB 트랜잭션 업데이트
- **Step 3 (FE 응답)**: 갱신된 연료 총량과 기록 성공 응답을 HTTP 200 OK로 반환

---

## 3. 하이브리드 Food Vision AI 스캔 & 식단 확정 비즈니스 로직 (`/api/v3/food-vision/*`)

### 3.1 `POST /api/v3/food-vision/scan` (음식 사진 분석 수신 후)
- **Step 1 (BE 512px 압축)**: 수신된 원본 이미지를 BE `sharp` 라이브러리로 512x512 Low-Res 이미지로 압축
- **Step 2 (BE 내장 YOLO 1차 검토)**: 압축 이미지에 대해 자체 경량 YOLO 모델로 1차 음식 식별 수행
  - **식별 성공 시**: 외부 API 호출 없이 0원 비용으로 즉시 영양성분 데이터 파싱 후 FE 전달
  - **미식별 / 불분명 시**: BE가 AI-server (`POST /v1/vision/scan`)로 Fallback 추가 분석 요청
- **Step 3 (FE 응답)**: 음식 식별 태그 및 3대 영양소/칼로리 데이터를 FE에 반환 (DB 저장 안 함, 수동 검수 카드 출력)

### 3.2 `POST /api/v3/food-log/confirm` (수동 검수 확정 등록 수신 후)
- **Step 1 (DB 적재)**: 사용자가 최종 검수한 식단 데이터를 `food_logs` 테이블에 적재 (칼로리, 탄단지 수치)
- **Step 2 (보상 지급)**: 사용자 연료 **+20 Fuel** 충전
- **Step 3 (FE 응답)**: 기록 확정 성공 메시지 반환

## 4. 별여행 탐사 & 비동기 리포트 생성 비즈니스 로직 (`/api/v3/planet-travel/*`, `/api/v3/reports/*`)

### 4.1 `POST /api/v3/planet-travel/start` (별여행 탐사 출발 수신 후)
- **Step 1 (연료 차감 & DB 업데이트)**: 사용자 보유 연료 차감 및 `planet_travels` 테이블에 탐사 상태 `IN_PROGRESS` 레코드 생성
- **Step 2 (Task Queue 작업 등록)**: BullMQ / Redis Task Queue에 리포트 생성 백그라운드 작업 Push
- **Step 3 (즉시 응답)**: 클라이언트에 `202 Accepted` 탐사 출발 응답 반환

### 4.2 백그라운드 Worker & 푸시 알림 로직
- **Step 1 (데이터 집계)**: Worker가 선택된 행성 테마(식사, 수분, 감정, 생활습관, 회고) 관련 사용자 기록 데이터 집계
- **Step 2 (AI-server 요약 요청)**: AI-server (`POST /v1/reports/summarize`)로 맞춤 리포트 생성 요청
- **Step 3 (DB 저장 & 푸시 발송)**: 생성된 리포트를 `reports` DB에 적재 후, 탐사 상태를 `COMPLETED`로 변경하고 FCM/APNs 서비스로 디바이스 푸시 알림 발송

### 4.3 `GET /api/v3/reports/{reportId}` (리포트 상세 조회 수신 후)
- DB에서 저장된 맞춤 AI 인사이트 리포트 상세 데이터 반환

## 5. AI 심리 공감 대화 & Undo 복구 비즈니스 로직 (`/api/v3/chat/*`)

### 5.1 `POST /api/v3/chat/message` (사용자 메시지 수신 후)
- **Step 1 (DB 즉시 선저장)**: `chat_messages` 테이블에 사용자 입력 메시지 (`sender: USER`) 저장
- **Step 2 (AI-server 전달 & 종합 가공)**: AI-server (`POST /v1/chat/process`)로 메시지 및 사용자 맥락 수치 전달 -> AI-server 내부에서 심리 공감 응답 생성 및 감정/웰니스 관련 내용 종합 가공
- **Step 3 (AI 응답 DB 저장)**: AI 가공 응답 텍스트를 `chat_messages` (`sender: TAMMY_AI`)로 DB 적재
- **Step 4 (FE 응답)**: 타미 공감 응답 텍스트와 모션 표정 태그를 FE로 최종 반환

### 5.2 `DELETE /api/v3/chat/messages/{id}` (대화 삭제 수신 후)
- 지정 메시지를 소프트 삭제(`isDeleted = true`) 처리

### 5.3 `POST /api/v3/chat/messages/{id}/undo` (Undo 복구 수신 후)
- 5초 이내 요청 시 해당 메시지의 소프트 삭제 상태를 해제(`isDeleted = false`)하여 대화 복원

## 6. 상시 웰니스 대시보드 비즈니스 로직 (`GET /api/v3/dashboard/summary`)

- 최근 일간/주간 섭취 칼로리 추이, 3대 영양소 비율, 수분 섭취량, 미션 완료 현황을 SQL 집계 후 차트 시각화 데이터 형태로 반환

---

## 7. 회원 인증 & 계정 관리 비즈니스 로직 (`/api/v3/auth/*`)

- `POST /api/v3/auth/register`: 회원가입 ➔ 비밀번호 단방향 암호화 DB 저장
- `POST /api/v3/auth/login`: 비밀번호 검증 ➔ Access/Refresh Token 발급
- `POST /api/v3/auth/refresh`: RTR 보안 정책 적용 Token 재발급
- `POST /api/v3/auth/withdraw`: 사용자 상태 `WITHDRAWN` 변경, 세션 무효화 및 데이터 익명화/지연 삭제 처리
