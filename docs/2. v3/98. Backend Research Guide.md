# 🔍 Backend Key Focus & Research Guide (백엔드 핵심 조사 가이드)

> 본 문서는 **채팅과 사진 전송**이 주 트래픽을 이루는 서비스 특성을 바탕으로, **Node.js 메인 백엔드 서버**의 반응성, 메모리 안정성, 및 DB 저장 비동기화를 극대화하기 위한 핵심 고민 및 기술 조사 항목을 정리한 가이드입니다.

---

## 1. 서비스 트래픽 특성 분석 (Traffic Characteristics)

- **실시간 대화 (Realtime Chatting)**: 사용자 발화 입력 시 최단 시간(Low Latency) 내에 타자기 효과 스트리밍 응답을 제공해야 합니다.
- **멀티모달 이미지 (Multimodal Photo Upload)**: 식사 및 일상 사진의 빈번한 업로드 요청을 받아 AI Vision 분석 엔진으로 실시간 중계해야 합니다.

---

## 2. 백엔드 3대 핵심 집중 과제 (TOP 3 Key Focus Areas)

### 2.1 실시간 대화 반응성 (HTTP REST + SSE 기반 TTFT 최소화)
- **목표**: 첫 글자 응답 생성 시간(TTFT) 최소화 및 복잡한 소켓 세션 없이 텍스트 스트리밍 제공.
- **핵심 과제**: 
  - WebSocket 대신 **HTTP REST (`POST /chat/messages`) + SSE (Server-Sent Events)** 조합을 도입하여 소켓 연결 수명주기(Heartbeat/Reconnection) 오버헤드 제거.
  - `Client` ↔ `Node.js Gateway` ↔ `AI Server` 스트리밍 통로에서 버퍼링 없이 즉시 전송하는 **Zero-buffering SSE Pipeline** 구축.

### 2.2 고용량 사진 전송 메모리 과부하 방지 & 비동기 DB 저장 (Stream Piping & Write-Behind Queue)
- **목표**: 사진 업로드 시 백엔드 메모리 스파이크 차단 및 AI Vision 분석 속도 최우선 보장.
- **핵심 과제**: 
  - **AI Server 처리 (실시간)**: 클라이언트 사진 데이터를 백엔드 메모리/디스크에 적재하지 않고 AI Server로 즉시 흘려보내는 **Pass-through Stream Piping** 적용.
  - **DB & 스토리지 저장 (비동기 큐)**: 사진의 S3 저장 및 DB 메타데이터(URL, 이미지 정보) 기록은 **Queue(큐)**에 넣어 백그라운드 Worker가 처리하는 **Write-Behind Queue 패턴** 도입.

### 2.3 DB 저장 및 AI 대화 스트리밍의 '완전 분리' (Non-blocking Write)
- **목표**: 100% 대화 로그(MySQL) 및 감정 임베딩(Pinecone) 저장이 실시간 대화 응답 속도를 지연시키지 않도록 보장.
- **핵심 과제**: 대화 전달 루프와 DB Write 루프를 이벤트 기반 비동기 큐(Event-Driven Queue)로 완전 분리.

## 3. 세부 기술 조사 과제 (Detailed Research Tasks)

### 3.1 [통신 프로토콜] HTTP REST + SSE (Server-Sent Events) 스트리밍 파이프라인
- **조사 내용**: WebSocket 대비 HTTP REST + SSE 조합의 메모리 효율성, 세션 유지 오버헤드 감축 효과 및 Nginx/로드밸런서 환경에서의 SSE 프록시 버퍼링 해제 기법(`X-Accel-Buffering: no`) 조사.
- **목적**: 불필요한 소켓 연결 관리 오버헤드를 없애고 ChatGPT 표준 방식의 단순화된 스트리밍 구축.

### 3.2 [이미지 처리 & 비동기 큐] Pass-through Stream Piping & Write-Behind DB Queue
- **조사 내용**: 
  - Multipart 사진 요청 데이터를 RAM에 적재하지 않고 AI Server로 Direct Piping하는 기법.
  - S3 Upload 및 MySQL DB 메타데이터 기록을 Queue(BullMQ/Redis)로 이격하여 처리하는 Write-Behind 패턴 조사.
- **목적**: 사진 업로드 시 즉각적인 AI 분석 반응성을 보장하고, DB 지연이 일어쳐도 사진 기능이 멈추지 않는 내구성(Fault Tolerance) 확보.

### 3.3 [비동기 저장] Event-driven Queue 기반 DB 저장 파이프라인
- **조사 내용**: BullMQ 또는 Redis PubSub을 활용하여 대화 및 임베딩 저장 요청을 비동기 Worker 큐로 넘기는 설계 조사.
- **목적**: DB 서버 지연/장애가 발생해도 클라이언트 실시간 대화 서비스는 영향을 받지 않도록 격리.

### 3.4 [확장성] Stateless HTTP REST + SSE 스케일아웃 설계
- **조사 내용**: WebSocket 세션 공유용 Redis Adapter 없이, 완전 무상태(Stateless) HTTP REST + SSE 환경에서의 손쉬운 인스턴스 수평 확장(Scale-out) 구조 검토.
- **목적**: 인프라 복잡도를 대폭 줄인 무중단 확장 구조 확보.
