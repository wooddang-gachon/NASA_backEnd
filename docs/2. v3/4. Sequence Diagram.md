# TAMMY v3 시퀀스 다이어그램 (Sequence Diagrams)

본 문서는 FE, BE, DB, AI-server 간의 데이터 흐름과 시스템 간 인터랙션을 정의합니다. 백엔드 컨트롤러 구현(`src/api/routes`)과 100% 일치하도록 작성되었습니다.

---

## 1. 1-Tap 퀵버튼 기록 & 연료(Fuel) 충전 시퀀스

사용자가 1-Tap 퀵버튼으로 데일리 웰니스 항목을 기록하고 우주 연료(Fuel)를 적립하는 과정입니다.

```mermaid
sequenceDiagram
    autonumber
    actor User as 사용자
    participant FE as FE (App Frontend)
    participant BE as BE (Backend Server)
    participant DB as DB (Main DB)

    User->>FE: 1-Tap 퀵버튼 클릭 (물/감정/일기/운동)
    FE->>BE: POST /api/quick-log (category, amount, emotionType, journalContent, exerciseName, durationMinutes)
    BE->>DB: 데일리 기록 저장 (Water/Emotion/Journal/Exercise)
    BE->>DB: 사용자 연료(Fuel) 계산 및 포인트 적립 (+10 Fuel)
    DB-->>BE: 저장 완료 및 갱신된 Fuel 반환
    BE-->>FE: HTTP 201 Created (ApiResponse: logId, category, earnedFuel, totalFuel)
    FE-->>User: Toast 알림 ("기록 완료! 연료 +10 충전") & UI 갱신
```

## 2. 별여행 탐사 & 탐사 결과(travelResult) 동기 생성 및 수령 시퀀스

연료를 소진하여 별여행 탐사를 출발하고, BE에서 행성 테마에 맞춰 AI-server (`X-Internal-Api-Key` 인증)로 동기 요청을 보내 탐사 결과(`travelResult`)를 생성하여 즉시 응답으로 수령하는 과정입니다.

```mermaid
sequenceDiagram
    autonumber
    actor User as 사용자
    participant FE as FE (App Frontend)
    participant BE as BE (Backend Server)
    participant DB as DB (Main DB)
    participant AI as AI-server (LLM Engine)

    User->>FE: 탐사 행성 선택 (MEAL/WATER/LIFESTYLE/EMOTION/RETROSPECT) 및 '별여행 출발' 클릭
    FE->>BE: POST /api/planet-travel/start { planetType, fuelSpent }
    BE->>DB: 연료(Fuel) 차감 & 탐사 상태(COMPLETED) 저장
    
    Note over BE, AI: 행성 테마별 AI 탐사 결과 동기 생성 (X-Internal-Api-Key)
    BE->>DB: 해당 행성 테마의 사용자 최근 기록 데이터 집계 조회
    DB-->>BE: 섭취/수분/운동/감정 기록 반환
    BE->>AI: POST /v1/reports/{diet|hydration|lifestyle|mindfulness|retrospective}
    AI-->>BE: AI 탐사 결과 응답 (title, markdown, nextActionChecks)
    
    BE->>DB: 탐사 결과(travelResult) DB 저장 및 planet_travels 연결
    DB-->>BE: 저장 완료 (travelResultId 생성)
    BE-->>FE: HTTP 200 OK (ApiResponse: travelId, travelResultId, remainingFuel, status, travelResult)
    FE-->>User: 별여행 완료 팝업 & 탐사 결과 진단서 화면 즉시 표시
    
    opt 우주여행 현황 조회 시
        User->>FE: 우주 탐사 현황 메인 화면 진입
        FE->>BE: GET /api/planet-travel/state
        BE->>DB: 현재 탐사 행성, 진행률, 보유 연료, 타미 관계 레벨 조회
        DB-->>BE: 우주여행 상태 데이터 반환
        BE-->>FE: HTTP 200 OK (ApiResponse: currentPlanet, explorationProgressPercent, currentFuel, requiredFuelForNextPlanet, tammyRelationshipLevel)
        FE->>User: 우주 탐사 대시보드 UI 표시
    end

    opt 탐사 결과 재조회 시
        User->>FE: 탐사 결과 목록/상세 클릭
        FE->>BE: GET /api/travel-results/{travelResultId} (또는 GET /api/reports/{reportId})
        BE->>DB: 탐사 결과 상세 데이터 조회
        DB-->>BE: travelResult Data
        BE-->>FE: HTTP 200 OK (ApiResponse: reportId, travelResultId, title, summaryContent, recommendations, createdAt)
        FE->>User: 행성 맞춤 탐사 결과 상세 화면 표시
    end
```

## 3. 사진 촬영, AI/YOLO 음식 검출 및 영양 매칭 시퀀스

식단 분석 및 기록 과정을 **(3.1) 음식 검출 API 시퀀스**, **(3.2) 식단 확정 API 시퀀스**, 그리고 **(3.3) 백엔드 내부 음식 검출 & AI-RDB 매칭 프로세스 플로우차트**로 명확히 분리하여 정의합니다.

### 3.1 사진 촬영 & 음식 검출 API 시퀀스

식단 사진 업로드 시 백엔드로 이미지를 전달하고 검출된 음식 명칭 및 바운딩 박스를 반환받는 클라이언트-서버 통신 시퀀스입니다.

```mermaid
sequenceDiagram
    autonumber
    actor User as 사용자
    participant FE as FE (App Frontend)
    participant BE as BE (Backend Server)

    User->>FE: 식단 사진 촬영 또는 갤러리 이미지 선택
    FE->>BE: POST /api/food-vision/scan (file: multipart/form-data, mealType)
    Note over BE: 백엔드 내부 음식 검출 프로세스 수행 (3.3 플로우차트 참조)
    BE-->>FE: HTTP 200 OK (ApiResponse: scanEngine, isFallbackUsed, detectedFoods)
    FE-->>User: 분석 결과 수동 검수 & 편집 카드 UI 표시
```

### 3.2 식단 확정 & 영양 기록 API 시퀀스

사용자 검수 후 식단을 확정하면 영양 성분을 매칭하고 식단 기록을 저장 및 연료를 적립하는 통신 시퀀스입니다.

```mermaid
sequenceDiagram
    autonumber
    actor User as 사용자
    participant FE as FE (App Frontend)
    participant BE as BE (Backend Server)
    participant DB as DB (Main DB)

    User->>FE: 음식 수량 수정 또는 수동 항목 추가 및 '기록 확정' 클릭
    FE->>BE: POST /api/food-log/confirm { mealType, foods }
    Note over BE, DB: 음식명 매칭 & 영양성치 DB 연동 프로세스 수행 (3.3 플로우차트 참조)
    BE-->>FE: HTTP 200 OK (ApiResponse: mealId, earnedFuel, totalCalories)
    FE-->>User: 메인 영양 대시보드 그래프 실시간 갱신 & 연료 적립 알림
```

### 3.3 백엔드 음식 검출 & AI-RDB 매칭 프로세스 (알고리즘 플로우차트)

백엔드 내부에서 수행되는 **(1) YOLO 1차 스캔 & Vision LLM Fallback 검출** 및 **(2) 매칭 테이블(food_mappings) 기반 RDB 영양 DB 매칭 & AI Lookup Fallback** 의사결정 프로세스입니다.

```mermaid
graph TD
    Start([1. 식단 사진 업로드 수신]) --> YOLO{자체 경량 YOLO 1차 스캔}
    
    YOLO -- 검출 성공 --> RawFood[인식된 음식명 도출]
    YOLO -- 미식별 / 불분명 --> Resize[이미지 압축 512x512 Low-Res]
    Resize --> VisionLLM[AI-server Vision LLM Fallback 요청]
    VisionLLM --> RawFood
    
    RawFood --> MatchTable{2. 음식 매칭 테이블 food_mappings 조회}
    
    MatchTable -- 매칭 성공: 표준 음식 존재 --> FetchRDB[표준 영양 DB foods에서 5대 영양성분 연결]
    MatchTable -- 매칭 실패: 미등록 음식 --> AILookup[AI-server 영양 Lookup 웹검색 요청]
    
    AILookup --> SaveRDB[foods 표준 영양 DB 저장]
    SaveRDB --> LearnMatch[food_mappings 매칭 테이블 자동 등록/학습]
    LearnMatch --> FetchRDB
    
    FetchRDB --> Complete([3. 식단 기록 DB 저장 & 연료 적립 완료])
```

## 4. AI 타미 심리 공감 대화 & AI-server 대화 시퀀스

사용자 메시지를 DB에 즉시 저장한 뒤, DB에서 최근 대화 히스토리(`ChatTurn[]`)를 추출하여 **AI-server (`POST /v1/chat/process`)**로 전달하고, 공감 응답 및 감정 상태/캐릭터 반응 모션을 수령하여 저장하는 과정입니다.

```mermaid
sequenceDiagram
    autonumber
    actor User as 사용자
    participant FE as FE (App Frontend)
    participant BE as BE (Backend Server)
    participant DB as DB (Main DB)
    participant AI as AI-server (LLM Engine)

    User->>FE: 메시지 입력 ("오늘 마음이 싱숭생숭해")
    FE->>BE: POST /api/chat/message { messageText }
    BE->>DB: 사용자 메시지 즉시 DB 저장
    DB-->>BE: 저장 완료
    BE->>DB: 최근 대화 히스토리 (10턴) 조회
    DB-->>BE: ChatTurn[] 히스토리 반환
    
    BE->>AI: POST /v1/chat/process (X-Internal-Api-Key, userId, userMessage, nickname, history)
    AI-->>BE: 응답 { replyText, emotion: { state, motionType } }
    
    BE->>DB: 타미 메시지 & 모션 태그(motion_tag) DB 저장 및 연료 적립 (+10 Fuel)
    DB-->>BE: 저장 완료
    BE-->>FE: HTTP 200 OK (ApiResponse: reply, motionTag, gainedFuel, currentFuel, emotion)
    FE-->>User: 타미 공감 대화 출력 & 캐릭터 모션 애니메이션 재생

    opt 메시지 소프트 삭제 및 복구 시
        User->>FE: 대화 메시지 삭제 클릭
        FE->>BE: DELETE /api/chat/messages/{messageId}
        BE->>DB: 해당 메시지 소프트 삭제 (is_deleted = true)
        DB-->>BE: 삭제 완료
        BE-->>FE: HTTP 200 OK (ApiResponse: data: null, message: "메시지가 성공적으로 삭제되었습니다.")
        
        Note over User, FE: 삭제 취소 (Undo) 동작 시
        User->>FE: '삭제 취소' 버튼 클릭
        FE->>BE: POST /api/chat/messages/{messageId}/undo
        BE->>DB: 해당 메시지 복구 (is_deleted = false)
        DB-->>BE: 복구 완료
        BE-->>FE: HTTP 200 OK (ApiResponse: data: null, message: "메시지 삭제가 취소되었습니다.")
    end
```

## 6. JWT 로그인 & Access Token 자동 갱신 시퀀스

사용자 로그인 시 토큰 발급 및 API 요청 중 Access Token 만료 시 FE 인터셉터를 통해 Refresh Token으로 자동 재발급받는 과정입니다.

```mermaid
sequenceDiagram
    autonumber
    actor User as 사용자
    participant FE as FE (App Frontend / Interceptor)
    participant BE as BE (Backend Server)
    participant DB as DB (Main DB)

    User->>FE: 이메일/소셜 로그인 요청
    FE->>BE: POST /api/auth/login (또는 POST /api/auth/social-login)
    BE->>DB: 사용자 검증 & Refresh Token 저장
    BE-->>FE: HTTP 200 OK (ApiResponse: user, accessToken, refreshToken)
    FE->>FE: Secure Storage에 토큰 저장

    Note over FE, BE: API 요청 중 Access Token 만료 발생
    FE->>BE: GET /api/users/me (Expired Access Token)
    BE-->>FE: HTTP 401 Unauthorized (Token Expired)
    
    FE->>BE: POST /api/auth/refresh (refreshToken)
    BE->>DB: DB 내 Refresh Token 검증
    DB-->>BE: 유효성 검증 성공
    BE-->>FE: HTTP 200 OK (ApiResponse: accessToken, refreshToken)
    FE->>BE: GET /api/users/me (새 Access Token으로 자동 재요청)
    BE-->>FE: HTTP 200 OK (ApiResponse: userId, nickname, gender, age, currentFuel, tammyStatus)
```

## 7. 회원 탈퇴 & 데이터 세션 정리 시퀀스

회원 탈퇴 요청 시 세션을 만료시키고 사용자 상태를 `WITHDRAWN`으로 변경하여 데이터 정리 및 세션을 삭제하는 과정입니다.

```mermaid
sequenceDiagram
    autonumber
    actor User as 사용자
    participant FE as FE (App Frontend)
    participant BE as BE (Backend Server)
    participant DB as DB (Main DB)

    User->>FE: '회원 탈퇴' 선택 및 최종 확인
    FE->>BE: POST /api/auth/withdraw (또는 DELETE /api/auth/withdraw)
    BE->>DB: 사용자 상태 WITHDRAWN 변경 & Refresh Token 삭제
    BE->>DB: 사용자 데이터 비식별화/세션 정리
    DB-->>BE: 처리 완료
    BE-->>FE: HTTP 200 OK (ApiResponse: userId, status: "WITHDRAWN")
    FE->>FE: 저장된 Local Storage / Secure Storage 세션 완전 삭제
    FE-->>User: 로그인/온보딩 화면으로 이동 ("회원 탈퇴가 완료되었습니다.")
```
