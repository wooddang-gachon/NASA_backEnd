## [AUTH] 인증 (AuthController → AuthService → AuthRepository)

### AUTH-001: 회원가입
- **엔드포인트**: `POST /api/auth/signup`
- **인증**: 불필요
- **입력**: `UserSignUpRequest` { email, password, nickname }
- **처리**:
  1. 이메일 중복 검사 (중복 시 `409 ConflictError`)
  2. argon2 비밀번호 해싱
  3. 트랜잭션으로 원자적 생성:
     - `users` 레코드 생성
     - `tammy_statuses` 초기화 (레벨 1, 경험치 0, 각 지수 50)
  4. JWT 토큰 발급 (AccessToken 1시간, RefreshToken 14일)
  5. RefreshToken DB 저장
- **출력**: `UserLoginResponse` { userId, email, nickname, accessToken, refreshToken }

### AUTH-002: 로그인
- **엔드포인트**: `POST /api/auth/login`
- **인증**: 불필요
- **입력**: `UserLoginRequest` { email, password }
- **처리**:
  1. 이메일로 사용자 조회 (미존재 시 `401 UnauthorizedError`)
  2. argon2 비밀번호 검증 (불일치 시 `401 UnauthorizedError`)
  3. JWT 토큰 발급 + RefreshToken 갱신
- **출력**: `UserLoginResponse`

### AUTH-003: 소셜 로그인
- **엔드포인트**: `POST /api/auth/social-login`
- **인증**: 불필요
- **입력**: `SocialLoginRequest` { provider: "GOOGLE"|"KAKAO"|"APPLE", token }
- **처리**:
  1. 외부 소셜 토큰 검증 (verifySocialToken)
     - Google: UserInfo API / TokenInfo API
     - Kakao: User ME API
     - Apple: 임시 구조
  2. 기존 회원이면 로그인, 신규면 자동 가입 + 토큰 발급
- **출력**: `UserLoginResponse`
- **에러**: 외부 검증 실패 시 `502 BadGatewayError`

### AUTH-004: 토큰 갱신
- **엔드포인트**: `POST /api/auth/refresh`
- **인증**: 불필요
- **입력**: `TokenRefreshRequest` { refreshToken }
- **처리**: RefreshToken 검증 → 새 AccessToken + RefreshToken 발급
- **출력**: `TokenRefreshResponse` { accessToken, refreshToken }

### AUTH-005: 회원 탈퇴
- **엔드포인트**: `POST /api/auth/withdraw` 또는 `DELETE /api/auth/withdraw`
- **인증**: JWT 필요
- **입력**: `UserWithdrawRequest?` { reason? }
- **출력**: `UserWithdrawResponse` { message }

## [CHT] AI 타미 심리 공감 대화 (ChatController → ChatService → ChatRepository + AiService)

### CHT-001: 대화 메시지 전송
- **엔드포인트**: `POST /api/chat/message`
- **인증**: JWT 필요
- **입력**: `ChatMessageApiRequest` { message }
- **처리**:
  1. 사용자 존재 확인 (없으면 `404 USER_NOT_FOUND`)
  2. 사용자 메시지 DB 저장 (sender: `USER`)
  3. 최근 10개 대화 히스토리 조회 (실패 시 빈 배열 Graceful degradation)
  4. AI 서버에 대화 요청 (`AiService.processChat`)
  5. AI 응답 메시지 DB 저장 (sender: `TAMMY_AI`)
     - emotion, motion_tag, intent_label, labels JSON 함께 저장
  6. 메모리 캡슐(extractedMemory) 있으면 별도 저장
  7. 사용자 연료 **+10** 적립 (`FUEL_REWARDS.CHAT`)
- **출력**: `ChatMessageApiResponse` { reply, motionTag, gainedFuel, currentFuel, emotion }

### CHT-002: 대화 메시지 삭제
- **엔드포인트**: `DELETE /api/chat/messages/{messageId}`
- **인증**: JWT 필요
- **처리**: 소프트 삭제 (`is_deleted = true`)
- **출력**: `{ message: string }`

### CHT-003: 대화 메시지 삭제 취소 (Undo)
- **엔드포인트**: `POST /api/chat/messages/{messageId}/undo`
- **인증**: JWT 필요
- **처리**: `is_deleted = false`로 복원
- **출력**: `{ message: string }`

## [FOD] 비전 스캔 & 영양 기록 (FoodController → FoodService → FoodRepository + LocalVisionService + AiService)

### FOD-001: 식단 사진 비전 스캔
- **엔드포인트**: `POST /api/food-vision/scan`
- **인증**: JWT 필요
- **입력**: `multipart/form-data` { file (이미지), mealType? (선택) }
- **제한**: 파일 최대 10MB, 이미지 MIME만 허용
- **처리**:
  1. 이미지 파일 `uploads/` 디렉토리에 저장
  2. `meal_images` 테이블에 이미지 메타데이터 등록
  3. **1차**: 로컬 ONNX YOLOv8 고속 탐지 (`LocalVisionService.detectFoodObjects`)
     - 640×640 Float32 NCHW 텐서 전처리 (Sharp)
     - 6개 클래스: 고등어구이, 김밥, 김치볶음밥, 불고기, 삼겹살, 양념치킨
     - 신뢰도/NMS 임계값: 0.45
  4. 탐지 실패 시 **2차**: AI 서버 Vision LLM Fallback (`AiService.analyzeFoodVision`)
     - 이미지 512×512 JPEG 압축 (품질 60%) → Base64
  5. 바운딩 박스 시각화 디버그 이미지 생성 (`*_debug.jpg`)
  6. 탐지된 음식별 영양 DB 스마트 매칭 (`FoodService.getOrMapFood`)
     - food_mappings 1차 → foods 토큰화 2차 → AI 추정치 3차 Fallback
- **출력**: `FoodVisionScanResponse` { imageId, imageUrl, debugImageUrl?, detectedItems[], scanSource }

### FOD-002: 식단 확정 등록
- **엔드포인트**: `POST /api/food-log/confirm`
- **인증**: JWT 필요
- **입력**: `FoodLogConfirmRequest` { imageId, imageUrl, mealType, items[] }
  - 각 item: { foodName, foodMappingId?, intakeGram, calories, carbohydrate, protein, fat, confidence?, boundingBox? }
- **처리** (트랜잭션):
  1. `meals` 레코드 생성 (총 영양 합산)
  2. `meal_items` (세부 음식) 레코드 생성
  3. `meal_images` 연결
  4. 사용자 연료 **+50** (`FUEL_REWARDS.FOOD_CONFIRM`)
  5. 타미 경험치 **+30** (`EXP_REWARDS.FOOD_CONFIRM`)
  6. `tammy_status_logs` 히스토리 기록
- **출력**: `MealLogRegisterResponse` { mealId, totalCalories, totalCarbohydrate, totalProtein, totalFat, itemCount, earnedFuel, earnedExp, currentFuel }

### FOD-003: 음식 검색
- **엔드포인트**: `FoodService.searchFoods(keyword)`
- **설명**: 식약처 15,568건 영양 DB에서 키워드로 음식 검색
- **출력**: `FoodSearchResponse` { foods[], totalCount }

## [TRV] 별여행 게이미피케이션 (TravelController → TravelService → TravelRepository + AiService)

### TRV-001: 행성 탐사 출발
- **엔드포인트**: `POST /api/planet-travel/start`
- **인증**: JWT 필요
- **입력**: `PlanetTravelStartApiRequest` { planetType }
  - planetType: `MEAL` | `WATER` | `EMOTION` | `LIFESTYLE` | `RETROSPECT`
- **처리**:
  1. 사용자 존재 확인 (없으면 `404 USER_NOT_FOUND`)
  2. 현재 연료 ≥ 필요 연료 검증 (부족 시 `400 INSUFFICIENT_FUEL`)
  3. 중복 진행 중인 탐사 검증 (있으면 `400 ALREADY_IN_PROGRESS_TRAVEL`)
  4. AI 서버에 행성별 진단서 생성 요청 (`AiService.generatePlanetReport`)
  5. `planet_travels` 레코드 생성
  6. 사용자 연료 차감
- **출력**: `PlanetTravelStartApiResponse` { travelId, travelResultId, remainingFuel, status, travelResult }

### TRV-002: 우주여행 현황 조회
- **엔드포인트**: `GET /api/planet-travel/state`
- **인증**: JWT 필요
- **출력**: `TravelStateInfoResponse` { currentPlanet, activePlanet, explorationProgressPercent, currentFuel, requiredFuelForNextPlanet(300), totalStarCount(5), completedStarCount, tammyRelationshipLevel, planetList[] }

### TRV-003: 탐사 결과 진단서 상세 조회
- **엔드포인트**: `GET /api/travel-results/{travelResultId}`
- **인증**: JWT 필요
- **출력**: `TravelResultDetailInfo` { reportId, travelResultId, userId, title, summaryContent, recommendations[], createdAt }

### TRV-004: 웰니스 대시보드 통계
- **엔드포인트**: `GET /api/dashboard/summary`
- **인증**: JWT 필요
- **입력**: Query `period?` (기본 7일, "MONTHLY"=30일)
- **출력**: `DashboardSummaryInfo` { period, caloriesTrend[], nutritionBalance, waterCount, exerciseCount, emotionCount, totalFuelEarned }
