## 1. 1-Tap 퀵버튼 기록 & 연료(Fuel) 충전 시퀀스

사용자가 1-Tap 퀵버튼으로 데일리 웰니스 항목을 기록하고 우주 연료(Fuel)를 적립하는 과정입니다.

```mermaid
sequenceDiagram
    autonumber
    actor User as 사용자
    participant FE as FE (App Frontend)
    participant BE as BE (Backend Server)
    participant DB as DB (MariaDB)

    User->>FE: 1-Tap 퀵버튼 클릭 (물/감정/일기/운동)
    FE->>BE: POST /api/quick-log { category, amount?, emotionType?, journalContent?, durationMinutes? }
    BE->>DB: 사용자 존재 확인 (users 조회)
    DB-->>BE: 사용자 정보 반환
    BE->>DB: quick_logs 레코드 생성 (earned_fuel: 10)
    BE->>DB: users.current_fuel += 10 (FUEL_REWARDS.QUICK_LOG)
    DB-->>BE: 저장 완료 및 갱신된 Fuel 반환
    BE-->>FE: HTTP 201 Created (ApiResponse: logId, category, earnedFuel, currentFuel)
    FE-->>User: Toast 알림 ("기록 완료! 연료 +10 충전") & UI 갱신
```

## 2. 별여행 탐사 & AI 진단서 동기 생성 시퀀스

연료를 소진하여 별여행 탐사를 출발하고, BE에서 AI-server로 동기 요청을 보내 진단서를 생성하여 즉시 응답하는 과정입니다.

```mermaid
sequenceDiagram
    autonumber
    actor User as 사용자
    participant FE as FE (App Frontend)
    participant BE as BE (Backend Server)
    participant DB as DB (MariaDB)
    participant AI as AI-server (Flask)

    User->>FE: 탐사 행성 선택 (MEAL/WATER/LIFESTYLE/EMOTION/RETROSPECT) 및 '별여행 출발' 클릭
    FE->>BE: POST /api/planet-travel/start { planetType }

    BE->>DB: 사용자 존재 확인 + 현재 연료 조회
    DB-->>BE: 사용자 정보 (current_fuel) 반환

    alt 연료 부족
        BE-->>FE: HTTP 400 Bad Request (INSUFFICIENT_FUEL)
    end

    BE->>DB: 진행 중인 탐사(IN_PROGRESS) 존재 여부 확인
    DB-->>BE: 탐사 상태 반환

    alt 중복 탐사
        BE-->>FE: HTTP 400 Bad Request (ALREADY_IN_PROGRESS_TRAVEL)
    end

    Note over BE, AI: 행성 테마별 AI 진단서 동기 생성 (X-Internal-Api-Key)
    BE->>AI: POST /v1/reports/{planetType} (userId, 사용자 기록 데이터)
    AI-->>BE: AI 진단서 응답 (title, summaryContent, recommendations)

    BE->>DB: planet_travels 레코드 생성 (status: COMPLETED, title, summary_content, recommendations)
    BE->>DB: users.current_fuel -= required_fuel (연료 차감)
    DB-->>BE: 저장 완료

    BE-->>FE: HTTP 201 Created (ApiResponse: travelId, travelResultId, remainingFuel, status, travelResult)
    FE-->>User: 별여행 완료 팝업 & 진단서 화면 즉시 표시

    opt 우주여행 현황 조회 시
        User->>FE: 우주 탐사 현황 메인 화면 진입
        FE->>BE: GET /api/planet-travel/state
        BE->>DB: 5개 행성 탐사 상태, 현재 연료, 타미 레벨 조회
        DB-->>BE: 상태 데이터 반환
        BE->>BE: TravelMapper로 진행률 계산 (PLANET_CONFIGS, WARP_FUEL_THRESHOLD)
        BE-->>FE: HTTP 200 OK (ApiResponse: currentPlanet, explorationProgressPercent, currentFuel, requiredFuelForNextPlanet: 300, totalStarCount: 5, completedStarCount, tammyRelationshipLevel, planetList)
        FE->>User: 우주 탐사 대시보드 UI 표시
    end

    opt 탐사 결과 재조회 시
        User->>FE: 탐사 결과 목록/상세 클릭
        FE->>BE: GET /api/travel-results/{travelResultId}
        BE->>DB: planet_travels 상세 데이터 조회
        DB-->>BE: 탐사 결과 데이터 반환
        BE-->>FE: HTTP 200 OK (ApiResponse: reportId, travelResultId, userId, title, summaryContent, recommendations[], createdAt)
        FE->>User: 행성 맞춤 진단서 상세 화면 표시
    end
```


## 4. AI 타미 심리 공감 대화 & AI-server 대화 시퀀스

사용자 메시지를 DB에 즉시 저장한 뒤, 최근 대화 히스토리를 추출하여 AI-server(`POST /v1/chat/process`)로 전달하고, 공감 응답 및 감정 상태/캐릭터 반응 모션을 수령하여 저장하는 과정입니다.

```mermaid
sequenceDiagram
    autonumber
    actor User as 사용자
    participant FE as FE (App Frontend)
    participant BE as BE (Backend Server)
    participant DB as DB (MariaDB)
    participant AI as AI-server (Flask)

    User->>FE: 메시지 입력 ("오늘 마음이 싱숭생숭해")
    FE->>BE: POST /api/chat/message { message }

    BE->>DB: 사용자 존재 확인 (users 조회)
    DB-->>BE: 사용자 정보 반환

    BE->>DB: 사용자 메시지 즉시 DB 저장 (sender: USER)
    DB-->>BE: 저장 완료

    BE->>DB: 최근 대화 히스토리 10건 조회
    DB-->>BE: ChatTurn[] 히스토리 반환
    Note over BE: 히스토리 조회 실패 시 빈 배열로 Graceful degradation

    BE->>AI: POST /v1/chat/process (X-Internal-Api-Key, userId, userMessage, nickname, history)
    AI-->>BE: 응답 { reply, emotion, motionTag, intentLabel, extractedMemory? }

    BE->>DB: AI 응답 메시지 DB 저장 (sender: TAMMY_AI, emotion, motion_tag, intent_label, labels)
    DB-->>BE: 저장 완료

    opt 메모리 캡슐 존재 시
        BE->>DB: extractedMemory 별도 저장
    end

    BE->>DB: users.current_fuel += 10 (FUEL_REWARDS.CHAT)
    DB-->>BE: 갱신된 Fuel 반환

    BE-->>FE: HTTP 200 OK (ApiResponse: reply, motionTag, gainedFuel: 10, currentFuel, emotion)
    FE-->>User: 타미 공감 대화 출력 & 캐릭터 모션 애니메이션 재생

    opt 메시지 소프트 삭제 및 복구 시
        User->>FE: 대화 메시지 삭제 클릭
        FE->>BE: DELETE /api/chat/messages/{messageId}
        BE->>DB: 해당 메시지 소프트 삭제 (is_deleted = true)
        DB-->>BE: 삭제 완료
        BE-->>FE: HTTP 200 OK (ApiResponse: { message: "메시지가 성공적으로 삭제되었습니다." })

        Note over User, FE: 삭제 취소 (Undo) 동작 시
        User->>FE: '삭제 취소' 버튼 클릭
        FE->>BE: POST /api/chat/messages/{messageId}/undo
        BE->>DB: 해당 메시지 복구 (is_deleted = false)
        DB-->>BE: 복구 완료
        BE-->>FE: HTTP 200 OK (ApiResponse: { message: "메시지 삭제가 취소되었습니다." })
    end
```

## 6. JWT 로그인 & Access Token 자동 갱신 시퀀스

사용자 로그인 시 토큰 발급 및 API 요청 중 Access Token 만료 시 Refresh Token으로 자동 재발급받는 과정입니다.

```mermaid
sequenceDiagram
    autonumber
    actor User as 사용자
    participant FE as FE (App Frontend / Interceptor)
    participant BE as BE (Backend Server)
    participant DB as DB (MariaDB)

    User->>FE: 이메일/소셜 로그인 요청
    FE->>BE: POST /api/auth/login (또는 POST /api/auth/social-login)
    BE->>DB: 사용자 검증 (email + argon2 비밀번호 또는 소셜 토큰 외부 검증)
    BE->>BE: JWT AccessToken (1시간) + RefreshToken (14일) 생성
    BE->>DB: RefreshToken DB 저장
    BE-->>FE: HTTP 200 OK (ApiResponse: userId, email, nickname, accessToken, refreshToken)
    FE->>FE: Secure Storage에 토큰 저장

    Note over FE, BE: API 요청 중 Access Token 만료 발생
    FE->>BE: GET /api/users/me (Expired Access Token)
    BE-->>FE: HTTP 401 Unauthorized (Token Expired)

    FE->>BE: POST /api/auth/refresh { refreshToken }
    BE->>DB: DB 내 Refresh Token 검증
    DB-->>BE: 유효성 검증 성공
    BE->>BE: 새 AccessToken + RefreshToken 발급
    BE->>DB: 새 RefreshToken DB 갱신
    BE-->>FE: HTTP 200 OK (ApiResponse: accessToken, refreshToken)
    FE->>BE: GET /api/users/me (새 Access Token으로 자동 재요청)
    BE-->>FE: HTTP 200 OK (ApiResponse: userId, email, nickname, profileImageUrl, tammy: {level, currentExp, ...}, currentFuel)
```

```mermaid
        DB-->>BE: 변동 이력 반환
        BE-->>FE: HTTP 200 OK (ApiResponse: history[]: {changeReason, expBefore, expAfter, levelBefore, levelAfter, createdAt})
        FE->>User: 타미 성장 히스토리 타임라인 표시
    end
```

## 10. 푸시 토큰 등록 시퀀스

```mermaid
sequenceDiagram
```
