# 🌐 HTTP 응답 상태 코드 레퍼런스 가이드 (HTTP Status Codes)

> 본 문서는 [MDN Web Docs - HTTP 상태 코드](https://developer.mozilla.org/ko/docs/Web/HTTP/Reference/Status) 명세를 기반으로 백엔드 및 REST API 개발 시 자주 사용되는 HTTP 응답 상태 코드를 요약 정리한 참고 문서입니다.

---

## 📌 1. 개요 및 상태 코드 5가지 클래스

HTTP 응답 상태 코드는 특정 HTTP 요청이 성공적으로 완료되었는지 여부를 3자리 숫자로 나타냅니다. 응답 코드는 크게 5가지 그룹으로 분류됩니다:

- **1xx (정보 제공 응답)**: 요청을 받았으며 작업을 계속 진행 중임
- **2xx (성공 응답)**: 클라이언트의 요청이 성공적으로 수신되어 이해되고 수락됨
- **3xx (리다이렉션 메시지)**: 요청을 완료하기 위해 추가적인 조치가 필요함
- **4xx (클라이언트 에러 응답)**: 클라이언트의 요청에 올바르지 않은 구문이나 권한 부재 등의 오류가 있음
- **5xx (서버 에러 응답)**: 서버가 유효한 요청을 수행하지 못하고 내부 오류를 발생시킴

---

## ℹ️ 2. 1xx 정보 제공 응답 (Informational Responses)

| 상태 코드 | 명칭 | 설명 |
| :--- | :--- | :--- |
| **100** | **Continue** | 클라이언트가 요청 헤더를 보낸 후 본문(Body)을 계속 전송해도 좋음을 의미합니다. |
| **101** | **Switching Protocols** | 클라이언트의 Upgrade 요청 헤더에 따라 서버가 프로토콜을 변경함(예: WebSocket 전환)을 알려줍니다. |
| **102** | **Processing** (WebDAV) | 서버가 요청을 수신하여 처리 중이지만 아직 응답을 사용할 수 없음을 나타냅니다. |
| **103** | **Early Hints** | 서버가 최종 응답을 준비하는 동안 클라이언트가 리소스를 사전 로딩(Preload)할 수 있도록 힌트를 제공합니다. |

---

## ✅ 3. 2xx 성공 응답 (Successful Responses)

| 상태 코드 | 명칭 | 설명 |
| :--- | :--- | :--- |
| **200** | **OK** | 요청이 성공적으로 완료되었습니다. (GET: 리소스 반환, POST: 작업 결과 반환) |
| **201** | **Created** | 요청이 성공하여 새로운 리소스가 생성되었습니다. (회원가입, 신규 데이터 등록 시 사용되며 `Location` 헤더에 리소스 URI 포함) |
| **202** | **Accepted** | 요청이 수락되었으나 아직 처리가 완료되지 않았음을 의미합니다. (비동기 백그라운드 작업 실행 시 사용) |
| **203** | **Non-Authoritative Info**| 돌려받은 메타데이터가 원본 서버가 아닌 대리 서버(Proxy)에서 수집된 정보임을 나타냅니다. |
| **204** | **No Content** | 요청이 성공했으나 응답 본문(Body)에 보내줄 데이터가 없습니다. (수정/삭제 완료 시 사용) |
| **205** | **Reset Content** | 요청 완료 후 클라이언트에게 폼 입력 화면 등을 초기화(Reset)하도록 지시합니다. |
| **206** | **Partial Content** | 클라이언트가 보내온 Range 헤더 요청에 따라 리소스의 일부분만 전송합니다. (동영상 스트리밍 등) |

---

## 🔀 4. 3xx 리다이렉션 메시지 (Redirection Messages)

| 상태 코드 | 명칭 | 설명 |
| :--- | :--- | :--- |
| **301** | **Moved Permanently** | 요청한 리소스의 URI가 영구적으로 변경되었습니다. (새로운 URI가 Location 헤더에 제공됨) |
| **302** | **Found** | 요청한 리소스의 URI가 일시적으로 변경되었습니다. (과거 302 Temporary Redirect) |
| **303** | **See Other** | 요청한 리소스를 다른 URI에서 GET 방식으로 가져와야 함을 지시합니다. |
| **304** | **Not Modified** | 캐시 목적으로 사용됩니다. 클라이언트에게 리소스가 수정되지 않았으므로 저장된 캐시를 그대로 사용하라고 알려줍니다. |
| **307** | **Temporary Redirect** | HTTP 메서드를 변경하지 않고 일시적으로 다른 URI로 리다이렉트합니다. |
| **308** | **Permanent Redirect** | HTTP 메서드를 변경하지 않고 영구적으로 다른 URI로 리다이렉트합니다. |

---

## ⚠️ 5. 4xx 클라이언트 에러 응답 (Client Error Responses)

| 상태 코드 | 명칭 | 설명 |
| :--- | :--- | :--- |
| **400** | **Bad Request** | 잘못된 문법이나 데이터 검증 실패로 인해 서버가 요청을 이해할 수 없습니다. (유효성 검사 실패 시 사용) |
| **401** | **Unauthorized** | 인증이 필요합니다. (비로그인 상태이거나 유효하지 않은 JWT 토큰 제출 시 사용) |
| **402** | **Payment Required** | 결제가 필요한 서비스에 사용하기 위해 예약된 상태 코드입니다. |
| **403** | **Forbidden** | 클라이언트가 리소스에 대한 접근 권한을 가지고 있지 않습니다. (로그인했으나 관리자 전용 기능 접근 시 사용) |
| **404** | **Not Found** | 요청한 리소스를 서버에서 찾을 수 없습니다. (존재하지 않는 URL 또는 유저 ID 조회 시 사용) |
| **405** | **Method Not Allowed** | 요청한 HTTP 메서드가 해당 엔드포인트에서 허용되지 않습니다. (예: POST만 지원하는 곳에 GET 호출) |
| **406** | **Not Acceptable** | Accept 헤더에 지정된 미디어 타입을 서버가 생성해 줄 수 없습니다. |
| **408** | **Request Timeout** | 서버의 요청 대기 시간이 초과되었습니다. |
| **409** | **Conflict** | 서버의 현재 상태와 요청이 충돌합니다. (이미 가입된 이메일 중복 등록 시 사용) |
| **410** | **Gone** | 요청한 리소스가 영구적으로 삭제되어 더 이상 사용할 수 없습니다. |
| **413** | **Payload Too Large** | 요청 본문의 크기가 서버가 처리할 수 있는 제한 범위를 초과했습니다. |
| **415** | **Unsupported Media Type**| 요청한 타겟의 데이터 포맷을 서버가 지원하지 않습니다. (예: JSON 대신 XML 전송 시) |
| **422** | **Unprocessable Content**| 요청 문법은 올바르나 논리적 오류로 인해 처리할 수 없습니다. |
| **429** | **Too Many Requests** | 일정 시간 동안 너무 많은 요청을 보냈습니다. (Rate Limiting 도배 방지 시 사용) |

---

## 💥 6. 5xx 서버 에러 응답 (Server Error Responses)

| 상태 코드 | 명칭 | 설명 |
| :--- | :--- | :--- |
| **500** | **Internal Server Error** | 서버 내부에서 처리되지 않은 알 수 없는 예외나 오류가 발생했습니다. |
| **501** | **Not Implemented** | 서버가 요청을 수행하는 데 필요한 기능을 지원하지 않습니다. |
| **502** | **Bad Gateway** | 게이트웨이 또는 프록시 서버가 연동된 상위 서버로부터 유효하지 않은 응답을 받았습니다. |
| **503** | **Service Unavailable** | 서버가 오버로드되거나 점검 중이어서 요청을 처리할 수 없습니다. (AI 연동 서버 다운 시 사용) |
| **504** | **Gateway Timeout** | 게이트웨이 또는 프록시 서버가 상위 서버의 응답을 제시간에 받지 못하고 타임아웃되었습니다. |
| **505** | **HTTP Version Not Supported**| 요청에 사용된 HTTP 프로토콜 버전을 서버가 지원하지 않습니다. |

## 🛠️ 7. NASA_backEnd 백엔드에서의 주요 상태 코드 활용 매핑

우리 백엔드 서비스에서는 아래 표준 상태 코드로 에러 응답을 예외 처리하고 있습니다:

- **`200 OK`**: 기본 데이터 조회 성공 (프로필 조회, 대시보드 조회)
- **`201 Created`**: 식단 등록, 회원가입 완료
- **`400 BAD_REQUEST`**: TSOA 쿼리/바디 유효성 검사 실패
- **`401 UNAUTHORIZED`**: JWT 토큰 만료 또는 로그인 실패
- **`403 FORBIDDEN`**: 타인의 데이터 수정 권한 없음
- **`404 NOT_FOUND` / `USER_NOT_FOUND`**: 존재하지 않는 유저 또는 리소스 조회
- **`409 CONFLICT`**: 이메일 중복 가입
- **`503 AI_SERVER_UNAVAILABLE`**: AI 타미 연동 서버 통신 실패
